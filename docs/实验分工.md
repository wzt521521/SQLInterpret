# 大型平台软件设计实习分工与验收标准

## 1. 项目目标与范围

本项目由 3 位成员共同完成一个中等难度的简化数据库管理系统（MiniDBMS）。系统应形成如下完整链路：

```text
SQL 文本
  -> 词法分析（Token）
  -> 语法分析（AST）
  -> 语义检查（Catalog）
  -> 逻辑执行计划（Plan）
  -> 执行引擎
  -> 行记录与数据页
  -> 缓存与磁盘文件
```

最终系统通过命令行界面接收 SQL，至少正确支持：

- `CREATE TABLE`
- `INSERT`
- `SELECT`（支持可选 `WHERE`）
- `DELETE`（支持可选 `WHERE`）

数据表和系统目录必须持久化，程序关闭并重新启动后，已经创建的表和插入的数据仍然可以查询。

以下分工按课件推荐的 Python 分层设计；如果最终选择其他语言，模块职责、数据结构和接口语义仍应保持一致。

本仓库采用 `src` 布局。下文中的 `sql_compiler/`、`storage/`、`engine/`、`cli/` 均位于 `src/minidbms/` 下。

### 1.1 中等难度基线

- 数据类型只要求 `INT`、`VARCHAR`，`BOOL` 仅作为表达式求值的内部类型。
- 比较运算支持 `=`、`!=`、`>`、`>=`、`<`、`<=`。
- 条件表达式支持 `AND`、`OR`、`NOT` 和括号，优先级为：括号 > `NOT` > 比较运算 > `AND` > `OR`。
- 使用顺序扫描，不要求实现索引扫描。
- 页大小统一为 4096 字节。
- 缓存替换支持 LRU 和 FIFO 两种策略，启动时可选择其中一种。
- DELETE 可以使用删除标记（tombstone），不强制立即整理页内空间。
- SQL 编译器至少实现两项简单规则优化：常量折叠、布尔表达式化简。

### 1.2 本次不要求实现

- `UPDATE`、`JOIN`、`GROUP BY`、`ORDER BY`、子查询和聚合函数。
- B+ 树、二级索引和成本优化器。
- 事务、WAL、并发控制、MVCC、崩溃恢复和访问控制。
- 完整兼容 MySQL/PostgreSQL 语法。

除非三个基础模块已经全部通过验收，不应提前增加上述扩展功能。

## 3. zby：SQL 编译器模块

### 3.1 功能需求

#### 3.1.1 词法分析器 Lexer

- 识别 SQL 关键字，关键字大小写不敏感。
- 识别标识符、整数、字符串常量、运算符、圆括号、逗号、分号。
- 支持单行注释 `-- ...`，建议同时支持块注释 `/* ... */`。
- 字符串内容保持原样，支持 SQL 风格单引号转义，例如 `'Tom''s book'`。
- 每个 Token 必须携带：
  - `type`：种别；
  - `lexeme`：原始词素；
  - `line`：从 1 开始的行号；
  - `column`：从 1 开始的列号。
- 非法字符、非法数字、字符串未闭合时必须抛出可定位的词法错误，程序不能崩溃。

#### 3.1.2 语法分析器 Parser

- 在 `grammar.md` 中明确写出实际支持的 SQL 子集文法，代码必须与文法一致。
- 构建结构化 AST，而不是只返回“语法正确”。
- 至少包含以下语句节点：
  - `CreateTableStmt`
  - `InsertStmt`
  - `SelectStmt`
  - `DeleteStmt`
- 至少包含以下表达式节点：
  - `IdentifierExpr`
  - `LiteralExpr`
  - `UnaryExpr`
  - `BinaryExpr`
- 正确处理 `AND`、`OR`、`NOT`、比较运算和括号的优先级。
- 支持一个输入中出现多条以分号结尾的 SQL 语句。
- 语法错误需要报告错误 Token 的位置、实际 Token 和期望符号。

#### 3.1.3 语义分析器 Semantic Analyzer

- 通过统一的 `CatalogView` 接口查询表结构，不自行维护与数据库引擎相互独立的第二份正式 Catalog。
- 检查创建表时表名是否重复、列名是否重复、类型是否受支持。
- 检查 INSERT、SELECT、DELETE 中的目标表是否存在。
- 检查引用列是否存在。
- 检查 INSERT 列数、列名、值数量和类型是否匹配。
- 检查比较运算两侧类型和逻辑运算操作数类型是否合法。
- 为已经绑定的标识符和表达式补充类型信息。
- 语义错误统一包含错误类型、源码位置和原因。

#### 3.1.4 逻辑执行计划与优化

- 将 AST 转换为统一 Plan 节点：
  - `CreateTablePlan`
  - `InsertPlan`
  - `SeqScanPlan`
  - `FilterPlan`
  - `ProjectPlan`
  - `DeletePlan`
- SELECT 的典型 Plan 结构为：

```text
Project[目标列]
  -> Filter[WHERE 条件，可省略]
       -> SeqScan[表名]
```

- DELETE 的典型 Plan 结构为：

```text
Delete[表名]
  -> Filter[WHERE 条件，可省略]
       -> SeqScan[表名]
```

- Plan 可以采用 Python 数据类作为内部表示，并提供树形文本或 JSON 格式输出。
- 至少实现两项优化：
  - 常量折叠，如 `10 + 8 -> 18`；
  - 布尔化简，如 `TRUE AND age > 18 -> age > 18`。
- 能同时展示优化前和优化后的 Plan，便于报告与验收。

### 3.2 zby 的交付物

- `sql_compiler/lexer.py`
- `sql_compiler/parser.py`
- `sql_compiler/ast.py`
- `sql_compiler/semantic.py`
- `sql_compiler/planner.py`
- `sql_compiler/optimizer.py`
- `sql_compiler/errors.py`
- `docs/grammar.md`
- `docs/sql_compiler_design.md`

### 3.3 zby 的验收标准

- 给定四类合法 SQL，能够依次输出 Token、AST、语义检查结果、优化前 Plan 和优化后 Plan。
- `select`、`SELECT`、`SeLeCt` 的处理结果一致。
- 表达式 `a = 1 OR b = 2 AND NOT c = 3` 的 AST 优先级正确。
- 缺少分号、括号不匹配、非法字符、未闭合字符串能够被拒绝并准确定位。
- 不存在的表/列、INSERT 值数量错误、INT/VARCHAR 类型不匹配能够在语义阶段被拒绝。
- 任意错误输入不得造成未捕获异常或进程退出。
- 单元测试覆盖四类合法 SQL，以及词法、语法、语义三类错误。
- 能在不修改存储系统代码的情况下，将生成的 Plan 交给 wzy 的执行引擎。

## 4. wzt：页式存储与缓存系统

### 4.1 功能需求

#### 4.1.1 磁盘文件与页管理

- 使用一个数据库文件或明确的数据文件集合保存页面。
- 固定 `PAGE_SIZE = 4096`，页号从确定的起点连续编号。
- 实现页的分配、释放、读取和覆盖写入。
- 读取不存在或已经释放的页时返回明确的存储错误。
- 写入内容超过 4096 字节时拒绝写入，短于 4096 字节时按统一规则补齐。
- 持久化页分配信息或空闲页列表，程序重启后不能重复分配仍在使用的页。
- 对外只暴露页号和 `bytes`，不解析表、列、行或 SQL。

#### 4.1.2 Buffer Pool

- 缓存容量可配置，测试时能够设置为较小容量以触发淘汰。
- 支持 LRU 和 FIFO 两种替换策略。
- 区分干净页与脏页，脏页被淘汰前必须写回磁盘。
- 实现单页刷新和全部刷新。
- 防止释放仍在使用的页；如实现 pin/unpin，则被 pin 的页不得淘汰。
- 记录以下统计数据：
  - 读取请求次数；
  - 缓存命中次数；
  - 缓存未命中次数；
  - 页面淘汰次数；
  - 脏页写回次数。
- 输出可读的命中与淘汰日志，便于实验报告截图。

#### 4.1.3 持久化与异常处理

- `flush_page`、`flush_all` 完成后，重新创建存储对象仍能读到相同字节。
- 文件不存在时可以初始化；文件损坏、页号非法、I/O 失败时返回统一存储错误。
- 正常退出时由数据库引擎调用 `flush_all`，存储模块本身也应提供安全关闭方法。

### 4.2 wzt 的交付物

- `storage/page.py`
- `storage/file_manager.py`
- `storage/buffer.py`
- `storage/storage_manager.py`
- `storage/errors.py`
- `docs/storage_design.md`
- `tests/test_storage.py`

### 4.3 wzt 的验收标准

- 能连续分配多个唯一页号，释放后能按既定规则安全复用。
- 任意不超过 4096 字节的数据写入后可原样读回。
- 关闭并重新打开程序后，页面内容和分配状态保持正确。
- 在容量为 2 的缓存中访问至少 3 个页面，LRU 和 FIFO 能产生预期且不同的淘汰顺序。
- 缓存重复读取同一页时命中计数正确。
- 修改脏页后触发淘汰，磁盘中的最终内容正确。
- 非法页号、超长页数据、已释放页访问均返回可理解的存储错误。
- wzy 只能通过约定的 `StorageManager` 接口完成读写，不需要访问缓存和文件管理器内部成员。

## 5. wzy：数据库引擎与总集成

### 5.1 功能需求

#### 5.1.1 持久化 Catalog

- Catalog 是表结构的唯一正式数据源，不能与 SQL 编译器各维护一份互不一致的表结构。
- 维护表名、列名、列顺序、列类型、表所拥有的数据页列表等元数据。
- Catalog 自身必须通过 wzt 的页式存储接口持久化，可作为特殊系统表或保留元数据页实现。
- 提供只读 `CatalogView` 给 zby 的语义分析器使用。
- CREATE 成功执行后立即更新 Catalog；重复表名必须报错。
- 程序重启后能够恢复全部表结构和数据页映射。

#### 5.1.2 行与页的映射

- 根据 Catalog 中的 Schema 将 Python 值序列化为字节，并支持反序列化。
- INT 使用统一的固定宽度编码；VARCHAR 使用长度前缀编码。
- 一个数据页能够保存多条记录；记录超过当前页剩余空间时分配新页。
- 页内至少保存记录数量、记录边界或槽信息，不能仅依赖换行符分隔二进制记录。
- DELETE 可以设置删除标记；SeqScan 必须跳过已删除记录。
- 单条记录大于页面可用空间时返回明确的执行或存储错误。

#### 5.1.3 执行引擎

- 解释 zby 生成的 Plan，不重新解析 SQL 文本。
- 实现以下执行逻辑：
  - `CreateTablePlan`：创建并持久化表元数据；
  - `InsertPlan`：按 Schema 检查并写入记录；
  - `SeqScanPlan`：逐页产生未删除的行；
  - `FilterPlan`：计算表达式并筛选行；
  - `ProjectPlan`：按目标列顺序返回结果；
  - `DeletePlan`：标记满足条件的记录并返回影响行数。
- 表达式求值结果必须与编译器的类型和优先级规则一致。
- 执行失败时不得产生半条记录或未登记的数据页；至少保证单条 SQL 的基础异常清理。

#### 5.1.4 CLI 与系统集成

- 提供 `MiniDB >` 命令行提示符，支持连续输入多条 SQL。
- 提供 `quit` 或 `exit` 命令，退出前刷新全部脏页。
- SELECT 以清晰表格或稳定文本格式输出列名和结果行。
- CREATE、INSERT、DELETE 返回成功信息和受影响行数。
- 捕获并格式化词法、语法、语义、执行和存储错误，CLI 不因单条错误 SQL 退出。
- 负责组织端到端测试、演示脚本和最终联调。

### 5.2 wzy 的交付物

- `engine/catalog_manager.py`
- `engine/record.py`
- `engine/storage_engine.py`
- `engine/executor.py`
- `engine/expression_eval.py`
- `cli/main.py`
- `docs/database_engine_design.md`
- `tests/test_db.py`
- `tests/e2e_demo.sql`

### 5.3 wzy 的验收标准

- 能完整执行“建表 -> 插入 -> 查询 -> 删除 -> 再查询”。
- SELECT 的列顺序、WHERE 过滤结果和返回行数正确。
- DELETE 只影响满足条件的记录，并返回准确的影响行数。
- 插入足够多的记录后能够跨多个页面存储和顺序扫描。
- 退出并重新启动后，表结构、数据、删除状态仍然正确。
- 重复建表、访问不存在的表/列、超大记录等错误能够由 CLI 清晰显示，系统继续运行。
- 端到端执行时可以查看 Buffer Pool 命中统计和淘汰日志。
- 不通过绕过 Plan、直接解析 SQL，或绕过 StorageManager、直接操作数据文件来完成测试。

## 6. 三个模块的统一对接标准

所有人应先共同确定以下接口，再分别开发。接口修改必须同步通知另外两人并更新本文件或接口文档。

### 6.1 公共基础类型

建议在 `common/` 中定义公共结构，避免三个模块各自定义同名但不兼容的类型。

```python
from dataclasses import dataclass
from enum import Enum
from typing import Any

class DataType(Enum):
    INT = "INT"
    VARCHAR = "VARCHAR"
    BOOL = "BOOL"          # 仅用于表达式内部结果

@dataclass(frozen=True)
class SourceLocation:
    line: int
    column: int

@dataclass(frozen=True)
class ColumnDef:
    name: str
    data_type: DataType

@dataclass(frozen=True)
class TableSchema:
    table_name: str
    columns: list[ColumnDef]
```

统一命名规则：SQL 关键字不区分大小写；表名和列名是否区分大小写必须由三人统一决定。为降低难度，建议表名和列名统一转为小写存入 Catalog。

### 6.2 错误接口

所有可展示给用户的错误统一继承 `DBError`：

```python
class DBError(Exception):
    stage: str       # LEXICAL / SYNTAX / SEMANTIC / EXECUTION / STORAGE
    code: str        # 稳定错误码
    message: str
    location: SourceLocation | None
```

约定：

- zby 负责产生词法、语法和语义错误。
- wzt 负责产生存储错误。
- wzy 负责产生执行错误，并在 CLI 统一格式化所有错误。
- 测试应优先断言 `stage` 和 `code`，不要只比较整段错误文本。

### 6.3 Catalog 对接：zby <-> wzy

wzy 提供只读查询接口，zby 的语义分析器只依赖该接口：

```python
class CatalogView:
    def table_exists(self, table_name: str) -> bool: ...
    def get_schema(self, table_name: str) -> TableSchema: ...
```

对接规则：

- 编译 CREATE 时，zby 只检查名称与定义并生成 `CreateTablePlan`，不能提前持久化 Catalog。
- wzy 执行 `CreateTablePlan` 成功后，才正式写入 Catalog。
- 编译后续语句时，语义分析器读取 wzy 已更新的 Catalog。
- zby 的单元测试可以使用内存版 `CatalogView` 假对象，但正式运行必须使用 wzy 的实现。

### 6.4 编译器与执行引擎对接：zby -> wzy

统一入口建议为：

```python
plans: list[PlanNode] = compiler.compile(sql_text, catalog_view)
result: ExecutionResult = executor.execute(plans[0])
```

`PlanNode` 中只保存执行所需的结构化信息，不允许把原始 SQL 交给执行器再次解析。表达式必须以 AST/Expression 节点传递，不能以任意 Python 表达式字符串交给 `eval()`。

`ExecutionResult` 统一为：

```python
@dataclass
class ExecutionResult:
    columns: list[str]
    rows: list[list[Any]]
    affected_rows: int
    message: str
```

约定：SELECT 使用 `columns` 和 `rows`；CREATE、INSERT、DELETE 主要使用 `affected_rows` 和 `message`。

### 6.5 数据库引擎与存储系统对接：wzy -> wzt

wzt 对外提供稳定的 `StorageManager`：

```python
class StorageManager:
    PAGE_SIZE = 4096

    def allocate_page(self) -> int: ...
    def free_page(self, page_id: int) -> None: ...
    def read_page(self, page_id: int) -> bytes: ...
    def write_page(self, page_id: int, data: bytes) -> None: ...
    def flush_page(self, page_id: int) -> None: ...
    def flush_all(self) -> None: ...
    def stats(self) -> dict[str, int]: ...
    def close(self) -> None: ...
```

对接规则：

- `read_page` 总是返回恰好 4096 字节。
- `write_page` 接受长度不超过 4096 的 `bytes`，禁止传入 Python 对象。
- wzy 决定页内如何存放行、删除标记和 Catalog；wzt 只保证页面可靠读写。
- wzy 不直接打开数据文件，也不访问 wzt 的内部缓存字典。
- 所有页修改最终必须通过 `write_page`，退出时由 wzy 调用 `flush_all` 和 `close`。

### 6.6 持久化约定

- 由 wzt 定义数据库文件的页寻址和空闲页管理格式。
- 由 wzy 定义 Catalog 页和普通表数据页的内容格式。
- 必须预留固定入口以定位 Catalog，例如固定元数据页号或数据库文件头中的 Catalog 根页号。
- 页格式必须带版本号或魔数；发现格式不匹配时应报错，不能把损坏内容当作正常数据读取。
- 测试目录使用临时数据库文件，不能覆盖人工演示数据。

## 7. 联调顺序与里程碑

### 里程碑 1：冻结公共接口

- 三人共同确认 SQL 子集、公共类型、错误结构、Plan 节点和 StorageManager 接口。
- zby 提供一组固定 Plan 样例。
- wzt 提供内存页或临时文件版 StorageManager 最小实现。
- wzy 提供 CatalogView 和 Executor 空壳。

完成标志：三个模块能够互相导入，基础接口测试通过。

### 里程碑 2：模块独立验收

- zby 用内存 CatalogView 完成 SQL 编译器测试。
- wzt 完成页读写、持久化、LRU/FIFO 测试。
- wzy 用手工构造的 Plan 和内存 StorageManager 完成执行器测试。

完成标志：各成员负责的单元测试独立通过。

### 里程碑 3：第一次端到端联调

仅打通以下最小链路：

```sql
CREATE TABLE student(id INT, name VARCHAR, age INT);
INSERT INTO student(id, name, age) VALUES (1, 'Alice', 20);
SELECT id, name FROM student WHERE age > 18;
```

完成标志：SQL 从文本进入，最终从数据页读回正确结果。

## 8. 小组联合验收用例

建议将以下内容保存为 `tests/e2e_demo.sql`，并另外编写自动化断言：

```sql
CREATE TABLE student(id INT, name VARCHAR, age INT);
INSERT INTO student(id, name, age) VALUES (1, 'Alice', 20);
INSERT INTO student(id, name, age) VALUES (2, 'Bob', 17);
INSERT INTO student(id, name, age) VALUES (3, 'Carol', 22);

SELECT id, name FROM student WHERE age >= 18 AND NOT name = 'Bob';
DELETE FROM student WHERE id = 1;
SELECT * FROM student;
```

必须验证：

1. 第一次 SELECT 只返回 Alice 和 Carol。
2. DELETE 返回影响 1 行。
3. 第二次 SELECT 不再返回 Alice，但仍返回 Bob 和 Carol。
4. 程序退出并重启后，第二次 SELECT 的结果保持不变。
5. 插入大量记录后发生跨页存储，查询结果仍然正确。
6. 使用很小的缓存容量执行扫描后，能够看到非零的缓存未命中和淘汰统计。
7. 再次执行相同查询时，缓存命中数按预期增加。
8. 重复 CREATE、错误列名、错误类型、缺分号和未闭合字符串分别在正确阶段报错。
